# Spec — Issue #3: Add deleteBuild method to API service

**Type:** feature

> Generated by Tsukinome. This file is the source of truth for the work; edits here drive the build.

## Summary

Add a deleteBuild(buildId: string) method to the frontend ApiService that issues an HTTP DELETE request to the /api/builds/:id endpoint, completing the CRUD interface for builds and matching the style of existing methods like getBuild and queryBuilds.

## Requirements

Each requirement is tagged with a confidence level (explicit / inferred / assumption / unknown).

- **R1** `[explicit]` ApiService exposes a public method deleteBuild(buildId: string).
- **R2** `[explicit]` deleteBuild issues an HTTP DELETE request to `${API_BASE}/api/builds/${buildId}`.
- **R3** `[explicit]` deleteBuild returns the HttpClient observable rather than subscribing internally, consistent with getBuild and queryBuilds.
- **R4** `[explicit]` deleteBuild follows the existing code style and typing conventions of the other ApiService methods.
- **R5** `[inferred]` The method's return type mirrors the generic/observable typing pattern used by getBuild (e.g. Observable of the delete response).

## Acceptance Criteria

### AC1

- **Given** An ApiService instance and a valid build id
- **When** deleteBuild(id) is called
- **Then** It sends an HTTP DELETE request to `${API_BASE}/api/builds/${id}`.

### AC2

- **Given** An ApiService instance
- **When** deleteBuild(id) is called
- **Then** It returns the HttpClient observable and does not subscribe internally.

### AC3

- **Given** The deleteBuild method
- **When** its signature and implementation are inspected
- **Then** It matches the style, typing, and endpoint-building pattern of getBuild/queryBuilds.

## Non-Goals

- No UI or button changes.
- No backend endpoint work; the DELETE endpoint is assumed to already exist or is out of scope.
- No changes to other ApiService methods.

## Edge Cases

- Empty or malformed buildId string passed to deleteBuild.
- buildId containing characters requiring URL encoding.
- Server responds with an error (e.g. 404 or 500) — error handling delegated to the caller via the returned observable.
